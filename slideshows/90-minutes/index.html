Section 2 · Anatomy · ★ remember this slide

The opt-in pair

block.json

"supports": { "interactivity": true }

Loads the engine — enqueues the @wordpress/interactivity runtime and makes view.js an ES module.

⇄

render.php

data-wp-interactive="iapi-gallery"

Gives the engine a place to bind — the hydration root; scopes every directive underneath it to the matching store.

Miss the flag → runtime never loads. Miss the directive → nothing to bind to. You need both.

Section 4 · IAPI Primer · 0:31–0:39

What is the Interactivity API?

A standardized way to add front-end interactivity to blocks — one pattern, shipped with Core.

  • Replaces ad-hoc per-plugin approaches (and their duplicate JS payloads)
  • Scales from a toggle button to live search, carts, instant navigation
  • Blocks can share state — "add to cart" in one block updates a separate cart block automatically

Already running in Core

  • Search
  • Query Loop
  • Navigation
  • File
  • Image lightbox
Section 4 · IAPI Primer

Under the hood

Preact + Signals

Hydration, client logic, and client-side navigation — tiny, and you never touch it directly.

HTML directives

data-wp-* attributes that both the client and the server understand.

HTML Tag Processor

Server-side logic in plain PHP — no Node.js SSR anywhere in the stack.

The trick is that both the client and the server can read the directives — that's what makes Section 7's no-flash first paint possible.

Section 4 · IAPI Primer

Declarative, not imperative

// imperative — the HOW
let sum = 0;
for ( let i = 0; i < nums.length; i++ ) {
    if ( nums[ i ] % 2 === 0 ) {
        sum += nums[ i ];
    }
}

You're micromanaging every move.

// declarative — the WHAT
nums
  .filter( ( n ) => n % 2 === 0 )
  .reduce( ( acc, n ) => acc + n, 0 );

You describe the result — all the machinery happens under the hood.

Directives work the same way: you describe what the UI should be for a given state — never how to update the DOM step by step.

Section 4 · IAPI Primer · ★ the mindset

Reactivity

  • When state changes, the UI updates automatically — you never manually touch the DOM
  • Each directive declares a relationship between an attribute and a piece of state
  • Mutation is allowed — you don't have to treat anything as immutable. ctx.currentSlide++ just works, and reactivity still fires

The state updates the UI — not the other way around.

Section 4 · IAPI Primer · ★ the loop

The round-trip loop

directivereads the store
eventfires an action
actionmutates context
re-renderdirectives update
⟲ …and the directives read again

Every section from here is this loop with more parts.

You do the mutation. The runtime does every re-render — that's the deal.

Section 4 · IAPI Primer

Anatomy of a directive

data-wp-bind--hidden---id

data-wp-

A standard HTML data-* attribute — valid markup, server-printable

bind

The directive name — what kind of relationship

--hidden

The parameter (two dashes) — which event, attribute, or CSS property

---id

Optional unique ID (three dashes) — lets the same directive appear more than once on one element

The --parameter pattern generalizes: any event, any attribute, any CSS property — and ---id when you need the same one twice.

Section 4 · IAPI Primer · ★ the distinction

Four kinds of data

Global state — when blocks share or sync data

wp_interactivity_state( 'storeName', array(
    'text' => __( 'This is the server side rendered text.' ),
) );
render.php

Local context — when each instance is independent

<div <?php echo wp_interactivity_data_wp_context(
    array( 'counter' => 0, 'isOpen' => true )
); ?>>
<!-- outputs: data-wp-context='{"counter":0,"isOpen":true}' -->
render.php

Derived state — when a value can be calculated

state: {
    get ucText() {
        return state.text.toUpperCase();
    },
},
view.js

Config — static, never triggers updates

wp_interactivity_config( 'storeName', array(
    'nonce' => wp_create_nonce( 'my_plugin_action' ),
) );
// view.js: const { nonce } = getConfig();
render.php · view.js

Context is per-instance. State is shared — and derived.

Section 4 · IAPI Primer

The server's role

  • No Node.js SSR — directives are processed in plain PHP through the HTML API
  • The browser gets fully rendered markup immediately — performance and SEO for free
  • The client doesn't re-render the page; it hydrates the server-painted state

The server paints the first frame; the client takes over without a flash.

Section 7 proves this on a throttled connection.

// PHP, at render time
<div <?php echo
  wp_interactivity_data_wp_context(
    array( 'currentSlide' => 1 )
  ); ?>>

  array( 'imageIndex' => '1/3' )

// view.js — the whole store, Section 5 edition
import { store, getContext } from '@wordpress/interactivity';

store( 'iapi-gallery', {
    state: {},
    actions: {
        nextImage: () => { getContext().currentSlide++; },
    },
} );

That's two of the store's three slots already — state and actions. The third one, callbacks, shows up in Section 8.

Section 6 · Sliding + Bounds · 0:49–0:59

Derived state

  • Disable logic is derived from currentSlide / totalSlides → it lives in state, not context
  • Getters re-run on every read — the UI stays in sync for free
  • New directives: data-wp-style--transform, data-wp-bind--disabled

This is the four-kinds slide from the primer paying off.

state: {
    get noPrevSlide() {
        const ctx = getContext();
        return ctx.currentSlide === 1;
    },
    get imageIndex() {
        const ctx = getContext();
        return `${ ctx.currentSlide }/${
                  ctx.totalSlides }`;
    },
    // + noNextSlide, slideTransform
}

The render filter walk

Land on the wrapper — next_tag()

Scan forward, counting slide classes
seek( 'main' ) — jump back
set_attribute( 'data-wp-context', … ) with the real count
add_filter(
  'render_block_iapi/gallery-slider',
  'iapi_gallery_slider_inject_context',
  10, 2

Exact hook name, exact block — the filter only ever sees our slider.

We do not set data-wp-interactive on inner blocks — descendants inherit the wrapper's namespace. ★

Section 8 · Autoplay

withScope in one slide

A requestAnimationFrame tick runs outside the Interactivity scope — without the wrapper, getContext() and state are undefined.

And the Section 2 promise pays off: speed is a string — coerce before you multiply.

const update = withScope( ( timestamp ) => {
    if ( timestamp - start >
         state.transitionsSpeed ) {
        actions.nextImage();
        start = null;
    }
    rafId = requestAnimationFrame( update );
} );

// the getter behind transitionsSpeed:
return Number( ctx.speed ) * 1000;
